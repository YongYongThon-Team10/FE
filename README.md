# 용인데이 · Frontend

용인 지역 행사 탐색과 하루 코스 설계 서비스입니다. Figma 디자인과 2026-11-09 기능명세서를 기준으로 React + TypeScript + Vite에서 구현했습니다.

## 이번 브랜치 변경사항 (2026-11-15)

1. 마이페이지 `/#/mypage`: 카테고리 6개 관심도, 음식 취향, 카페 특징, 별점 중요도 및 혼잡 회피 설정과 계정별 브라우저 보관.
2. 맞춤 추천 `/#/recommendations`: 질문, 선호도, 거리, 별점과 리뷰 및 예상 혼잡도를 반영한 후보 정렬과 근거 표시.
3. 목업 장소 10개, 혼잡도 장소 3개, 5초 간격 시연 재생과 수용인원 대비 체류, 유입 및 유출 상세 제공.
4. 실제 BE 연결 어댑터, 기본 30초 재조회, 탭 복귀 및 온라인 복구, 화면 이탈 시 취소와 실패 시 마지막 결과 표시.
5. 홈, 내 코스, 설정과 실제 코스 계획에서 새 취향 추천 흐름으로 연결.
6. 정적 검사, 프로덕션 빌드, Playwright 전체 73개 및 카카오 프록시 테스트 6개 통과. 마지막 설명 문구 보완 후 관련 계약 테스트 7개 재검증.

기본 `VITE_INTELLIGENCE_MODE=mock`은 데이터와 AI 판단 모두 시연 예시다. `api`는 실제 BE 경로를 호출하며 오류를 목업으로 대체하지 않는다. 신규 추천과 계정 선호도 API는 BE 구현이 필요하며 실제 OpenAI 계정 성공을 검증한 상태는 아니다.

BE 개발자에게 전달할 질문 분석, 추천과 혼잡도 AI의 역할, 점수식, 실제 정보 수집 경로 및 API 계약은 [BE 전달 Markdown](docs/BE_AI_SERVICE_HANDOFF.md)을 참고한다. 이전 검색, 날짜, 코스 및 공유 수정 기록은 [FE 변경 기록](docs/BUG_FIXES.md)에 보존했다.

## 실행

Node.js 24.14.1 / npm 11 기준입니다.

```bash
npm ci
npm run dev
```

기본 주소는 http://localhost:5173 입니다. 개발 모드는 Figma 시연 흐름을 유지하며, 운영 빌드는 카카오 REST API의 실제 장소 검색·주변 음식점/카페 선택·하루 코스 생성·지도·브라우저 저장을 제공합니다. [실제 장소 검색·서버·배포 안내](docs/REAL_PLACE_SEARCH.md)를 확인하세요.

운영 배포(Vercel): https://yongin-day.vercel.app

홈 추천은 에버랜드, 한국민속촌, 호암미술관, 와우정사, 용인농촌테마파크, 한택식물원의 실제 카카오 검색 결과를 확인해 표시합니다. 명소 본체만 선택하며 주차장과 부대시설은 추천에서 제외합니다. 일반 장소 검색은 사용자의 검색어를 그대로 지원합니다.

대표 명소는 실제 사진을 제공하며 카드, 코스 및 저장 목록에 연결합니다. BE의 `imageUrl`과 `thumbnailUrl`을 우선 표시하고 로딩 실패 시 기본 사진으로 복구합니다. [사진 출처와 BE 이미지 규격](docs/PLACE_IMAGES.md)을 확인하세요.

팀 BE Cloudtype 서버와 연결했습니다. 홈 통합 검색에서 장소와 실제 행사를 함께 찾고, '용인 축제와 행사 찾아보기'에서 날짜·지역별 목록, 상세, 출발지 검색 및 행사 기반 서버 일정 생성을 이용합니다. 행사 일정은 브라우저 편집본으로 가져와 수정·지도·저장·공유할 수 있습니다. 가입과 로그인, 로그아웃도 BE 인증을 사용합니다. 받은 문서의 26개 API 경로를 호출 모듈에 반영했습니다. [팀 BE 연동 안내](docs/TEAM_BACKEND_INTEGRATION.md)에서 실서버 검증과 남은 차이를 확인하세요. 개인 코스는 브라우저 저장이며 공용 데모 방식의 BE 저장을 개인 저장으로 전환하지 않았습니다. 데이터 적재 후 2026-11-15 당일 행사 150건, 2025~2027년 범위 1,751건을 확인했습니다.

지금까지 완료한 기능, 오류의 재현 상황·원인·해결 방법과 테스트 결과는 [FE 작업 및 오류 해결 기록](docs/BUG_FIXES.md)에 정리했습니다.

## 화면과 동작

- 홈: Figma `333:1021`의 코랄 배너·다리 그래픽, 검색창과 추천 행사. 문장/행사명 검색 한 번으로 결과로 이동하며 조건 선택은 결과 화면에서 제공.
- 행사 탐색: 목록/지도 전환, 날짜/거리 정렬, 마커 클릭 미리보기, 상세와 출처 차이·신청 채널.
- 코스: 아이 나이·출발지·이동수단·시간·활동 설정, 5칸 일정, 장소 교체/직접 입력/추가/삭제/순서 변경, 초과 시간 경고.
- 위치: 좌표 기반 마커·장소 정보, 현재 위치, 방문 순서 점선, 카카오맵 귀가 링크.
- 보관: 브라우저 내 저장·관심 행사, 일정 스냅샷 링크 공유·가져오기.
- 부가 화면: 로그인/가입/비밀번호 찾기, 계정/알림 선호/개인정보, 공지/문의, 이용 가이드.
- 이전 시설 서비스: 기흥 여가지도, 시설 검색·필터·상세, 이용 현황·주차·주변 행사, 정보 미제공·빈 결과·안내.

Figma `ui` 36개 + `Page 1` 이전 시설 14개, 총 **50개 제품 프레임**을 구현했습니다. [프레임별 대응표](docs/FIGMA_COVERAGE.md)에 원본 노드와 구현 경로를 기록했습니다. 실행 후 [전체 화면 비교 목록](http://localhost:5173/#/design-review)에서 고정된 비교 상태를 열 수 있습니다. 미리보기는 일반 보관 데이터와 분리됩니다. 이전 시설 서비스는 `#/facilities`입니다.

운영 홈은 `#/`, 통합 검색은 `#/search?q=검색어`, 실제 행사 목록은 `#/festivals`, 공개 행사 달력은 `#/calendar`, 장소 지도는 `#/map`, 내 코스는 `#/saved`, 설정은 `#/settings`입니다. `#/events`는 이전 행사 UI 경로이며 실제 장소 모드에서는 장소 목록으로 연결됩니다. 온보딩은 `#/onboarding`에서 확인할 수 있습니다.

## 백엔드와 n8n 연결

전체 클릭 여정과 상태 전달은 [프론트 서비스 흐름](docs/USER_FLOW.md)에서 확인할 수 있습니다. 게스트로 검색부터 일정 수정·지도·저장·공유까지 진행할 수 있습니다.

`.env.example`을 `.env.local`로 복사합니다.

```dotenv
VITE_API_BASE_URL=https://your-api.example.com/v1
VITE_DATA_REFRESH_MS=60000
```

주소를 비우면 시연 모드입니다. 주소를 설정하면 서버 모드이며, 오류 시 시연값으로 대체하지 않습니다. 최초/주기/탭 복귀/온라인 복구 시 재조회합니다. n8n 등 수집 작업이 DB와 갱신 시각을 업데이트하면 같은 데이터가 목록·상세·지도에 반영됩니다.

시설은 `GET /facilities`로 별도 조회하며 이용 인원·정원·주차 면수·관측 시각을 표시합니다. 미제공 수치를 0으로 채우지 않습니다. 시연 시설 지도는 가상 배치도이며 서버 데이터는 좌표 기반 지도로 표시합니다.

위 `VITE_API_BASE_URL`과 [API 규격 초안](docs/API_CONTRACT.md)은 이전 FE 제안 규격입니다. 현재 운영 팀 BE는 `VITE_TEAM_API_BASE_URL`, 실제 장소 프록시는 `VITE_PLACES_API_BASE`로 별도 설정합니다. 현재 경로와 실제 적용 범위는 [팀 BE 연동 안내](docs/TEAM_BACKEND_INTEGRATION.md)를 우선 확인하세요. [개발 단계와 명세 대응](docs/DEVELOPMENT_PLAN.md)은 초기 개발 계획 기록입니다.

현재 코스는 이 브라우저에 보관되며 계정별 동기화·실제 푸시 발송은 연결 전입니다. 문장 해석/코스 생성은 서버 모드에서 API를 호출하고, 시연 모드에서는 표시된 로컬 규칙만 사용합니다. 위치 좌표는 브라우저 저장소와 공유 링크에서 제외합니다. 실제 도로 경로·실시간 교통이 아닌 직선거리 기반 추정임을 표시합니다.

시연 계정으로 계정·로그아웃·탈퇴 흐름을 확인할 수 있습니다. 시연 문의는 실제 전송 없이 완료 화면을 보여 주며 이를 표시합니다. 서버 모드에서는 실제 성공 응답을 받은 뒤 완료 화면으로 이동합니다.

## 취향 맞춤 추천과 혼잡도 시연

`/#/mypage`에서 카테고리 관심도, 음식 취향, 카페 특징과 별점 중요도를 저장하고 `/#/recommendations`에서 질문, 반경과 취향을 함께 반영한 추천을 확인한다. 목업 장소 10곳의 별점 및 리뷰와 공원 등 3곳의 수용인원 기반 혼잡도를 제공한다. 5초 간격 시연 재생과 혼잡도 상세를 사용할 수 있다.

기본 `VITE_INTELLIGENCE_MODE=mock`은 질문 분석과 AI 판단도 명시적인 시연 예시이며 실제 OpenAI를 호출하지 않는다. `api`는 `VITE_TEAM_API_BASE_URL`의 추천, 계정 선호도와 혼잡도 경로를 사용하며 오류를 mock으로 바꾸지 않는다. 응답 완료 후 기본 30초 재조회, 탭 복귀와 온라인 복구, 화면 이탈 시 취소를 구현했다. 계정별 선호도는 현재 브라우저에 구분 저장하고 api 모드에서 로그인하면 서버 동기화를 요청한다.

BE 추천과 선호도 API는 추가 구현이 필요하다. 기존 로컬 BE 혼잡도는 고정 시연 시각만 지원하므로 실제 현시각 공급자로 확장해야 한다. 개발자에게 전달할 계산식, 실제 정보 수집 경로, OpenAI 역할과 요청 및 응답 계약은 [BE_AI_SERVICE_HANDOFF.md](docs/BE_AI_SERVICE_HANDOFF.md)를 참고한다.

## 검증

```bash
npm run check

```

Playwright 73개 테스트와 카카오 프록시 단위 테스트 6개가 통과했습니다. 전체 50개 프레임의 320/390/1280px 표시, 달력·필터·응답 검증, 위치 허용/거부, 코스 생성·편집·저장·공유, 통합 검색, 팀 BE 계약, 공유 수신자의 지도·저장, 실패·재시도·취소를 검사합니다. 모의 API/로컬 테스트이며 실제 인증 성공을 증명하지는 않습니다. 테스트용 서버는 5173(시연), 5174(이전 API), 5175(실제 장소 응답 모의), 5176(팀 BE 응답 모의), 5177(맞춤 추천 API 모의)에서 실행합니다. 운영 사이트 점검 결과는 [오류 해결 기록](docs/BUG_FIXES.md)에 별도로 정리했습니다.
