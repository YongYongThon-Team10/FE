## 2026-11-15 배포 재점검 후 FE 수정 — 운영 배포 대기

이 절은 이전 운영 검증 이후의 재점검 결과다. 사용자 요청에 따라 수정본을 `codex/fe-flow-fixes-20261115` 브랜치로 분리한다. 운영 배포는 별도 컨펌 전까지 진행하지 않는다.

- 배포 화면에서 11월 16일 입력 후 결과가 11월 15일로 표시되는 현상을 관찰했다. 일반 Playwright 날짜 입력으로는 기존 로컬 코드에서 재현되지 않았다. 입력기/자동 완성에 대한 방어로 제출한 폼의 실제 날짜·시작/종료 시간·이동수단·체류 시간을 읽어 코스에 반영한다. React change 이벤트 전에 날짜 컨트롤만 갱신되는 경우를 포함해 저장, 새로고침, 독립 브라우저의 공유·가져오기까지 검증했다. 특정 브라우저 문제를 확정한 것은 아니다.
- 일반 검색의 주차장·매표소·정류장 등은 주소·상세 링크와 지도 조회를 유지하되 하루 코스 시작 버튼을 제공하지 않는다. 명소·음식점·카페는 계속 선택할 수 있고, 화장실문화박물관처럼 단어를 포함하는 실제 명소를 일괄 제거하지 않는다.
- BE 네트워크 실패를 `NETWORK_ERROR`와 한국어 안내로 변환한다. 요청 취소와 시간 초과는 별도로 유지한다. 행사 조회 실패 시 실제 장소 탐색으로 이어지는 경로를 제공하고, 통합 검색의 장소 결과와 재시도는 독립적으로 유지한다. 실패를 행사 0건으로 표시하지 않는다.
- 실제 연결 모드의 설정·도움말 등 공통 화면은 시연 데이터 푸터 대신 공식 출처 확인 및 브라우저 보관 안내를 표시한다. 별도 Figma 시연 모드는 유지한다.

검증: `npm run check`, `npm run build`, Playwright 61개, 카카오 프록시 테스트 6개 통과. API 실패·재시도 및 별도 공유 수신자 테스트는 모의 응답 기반이며 실제 BE 복구·정상 인증 성공을 뜻하지 않는다.

현재 기존 Cloudtype 주소의 Swagger, `/v3/api-docs`, 행사 API가 HTTP 404를 반환하며 배포 FE의 행사 검색·목록·캘린더는 통신 실패 상태다. 이전의 행사 150건/291건 검증은 아래에 보존한 과거 결과이며 현재 가용성을 의미하지 않는다. 서버 주소·가용성·CORS 복구는 BE 확인이 필요하다. 사진·요금·영업시간도 제공되지 않는 정보는 생성하지 않는다.

## 검증 결과와 재현 확인

구현 완료 시 아래 검증이 통과했다. 이 문서는 검증 결과를 기록한 것이며 문서 작성 과정에서 동일한 테스트를 다시 실행한 것은 아니다.

- `npm run check`: lint, TypeScript, Prettier 검사 통과.
- `npm run build`: 프로덕션 빌드 통과.
- `npm test -- --workers=2`: Playwright **56개 통과**.
- `npm run test:server`: 카카오 프록시 단위 테스트 **6개 통과**.
- 테스트는 모의 API와 로컬 실행을 사용한다. 실제 회원가입·정상 로그인 성공을 실서버에서 검증했다는 뜻은 아니다.

주요 회귀 검증은 `tests/team-api.spec.ts`, `tests/real-places.spec.ts`, `tests/backend-contract.spec.ts`에 포함돼 있다. 캘린더 실패/재시도, 목록 복귀 및 새로고침, 여러 페이지의 행사 검색, 브라우저 편집본, 미정/자정 이후 시각, 체류 시간·순서 유지, 공유 수신자의 별도 브라우저 지도·저장을 확인한다.

운영 사이트에서는 다음 흐름을 직접 확인했다.

1. 2026-11-15 공개 행사 **150건**, 11월 공개 목록 **291건**. 달력에 당일 행사 150건 표시.
2. '상상플리마켓' 검색 시 실제 행사 1건 표시.
3. 실제 행사 상세 → 기흥역 출발지 선택 → 5개 슬롯의 서버 일정 생성.
4. 행사 일정을 브라우저 편집본으로 가져와 체류 시간 변경, 실제 레스토랑·카페 추가. 기존 행사들은 유지.
5. 카카오 지도·구간 길찾기·편집본 공유 미리보기·공유 지도 정상 표시. 확인한 최종 화면에서 브라우저 콘솔 오류 없음.
6. 점검 중 만든 서버 일정으로 추가/삭제/순서 변경/교체/재생성/공유/저장 API 정상 응답을 확인했고 테스트 저장 기록은 삭제했다. 다른 사용자의 일정은 수정하지 않았다.

최종 구현 배포 커밋은 `69ec5db`이며 Vercel 운영 주소에 반영했다. 이후 문서만 추가한 커밋은 구현 변경과 구분한다.

## 해결되지 않은 BE 의존 사항

- 사용자별 일정·코스 소유권 및 조회/수정/삭제 권한. 현재 공용 저장 API를 개인 저장으로 연결하지 않는다.
- 카카오 장소와 행사 편집본의 장소·좌표·순서·체류 시간 스냅샷 저장 계약 및 기기 간 동기화.
- 테스트 계정/환경과 로그인 유지 방식. 정상 인증의 실서버 성공, 두 계정 간 격리는 미검증이며 현재 새로고침하면 재로그인이 필요하다.
- 비밀번호 재설정·회원 탈퇴, 실제 문의·공지·푸시 발송 API.
- 행사 사진 URL과 출처, 운영 시간 미제공/`00:00 ~ 00:00` 구분, 실제 식사 후보. FE의 실제 맛집·카페는 카카오 조회를 유지한다.
- 개인 캘린더 API의 조회 범위 명시, 실제 공유 URL 설정, 행사 키워드 검색 API.

BE에 전달할 최신 요청 문구와 계약 차이는 [팀 BE 연동 안내](TEAM_BACKEND_INTEGRATION.md)에 정리했다.
