# FE 개발 단계와 기능명세서 대응

기준: 2026-11-09 백엔드 기능명세서, Figma `7h3RrrQLKuxoRTn70jSLn3`의 `ui` 페이지 36개와 사용자가 포함을 요청한 `Page 1`의 이전 시설 화면 14개. 총 50개 대응은 `FIGMA_COVERAGE.md`에 기록했다. API 규격이 없으므로 프론트 기능과 실제 서버 의존 작업을 구분했다.

## 1단계 — 디자인 기반 / 완료

- Noto Sans KR 400/500/700, Gugi 400을 로컬 번들로 제공한다.
- 파랑 `#2849B2`, 코랄 `#F56D5D`, 배경 `#F8F9FE`, 공통 여백·카드·탭을 적용했다.
- Figma 로고·아이콘·이미지를 원본 에셋으로 보관했다. `design-assets.json`에 출처 노드를 기록했다.
- 홈의 중복 스크롤·콘텐츠를 하나로 합쳤다. 달력은 서울 시간의 실제 요일·월·연도 경계를 계산한다.
- 일반 웹에서는 브라우저·safe area를 사용한다. 별도 화면 비교 모드는 원본 iOS 상태 표시줄과 홈 인디케이터를 재현하며 일반 보관 상태와 분리된다.

## 3단계 — 코스 구성 P1 / FE 구현

- 동행/아이 나이, 출발지 입력·현재 위치, 이동수단, 날짜/시간, 무료만, 활동 복수 선택.
- 위치 거부는 직접 입력으로 전환. 입력 누락·종료 시간 오류는 생성 전 안내.
- 행사 도착 → 프로그램 → 식사 → 근처 행사 → 귀가 5칸. 후보 부족은 빈칸과 이유로 표시.
- 행사/장소 추가·교체·직접 입력·삭제, 드래그 및 키보드 버튼 순서 변경.
- 수정 시 시간표·마커 순서 재계산. 종료 시간 초과는 경고하며 자동 삭제하지 않음.
- 좌표에 따른 직선거리 추정, 미확인 좌표/이동시간은 추정하지 않음.
- 시연 모드에서만 로컬 규칙 기반 생성. 서버 모드 생성/수정은 API 응답 사용. AI 추천·시간표 최적화 검증은 백엔드 연동 단계에 포함.

## 4단계 — 저장·공유와 부가 화면 / FE 구현

- 브라우저 코스/관심 행사 저장, 삭제 확인, 캘린더 필터.
- 공유 시점의 일정 링크, 다른 세션에서 열기·가져오기, 클립보드 거부 대응.
- 로그인·회원가입·비밀번호 찾기·계정·설정·알림 선호·개인정보·공지·문의·이용 가이드 화면.
- 서버 모드의 실제 인증/문의는 성공 응답 후에만 완료 표시. 명시적인 시연 계정과 실제 전송하지 않는 시연 문의 완료를 별도로 제공.
- 월간 달력, 생성 대기·오류·취소, 장소 교체·직접 입력·출발지·저장/공유·삭제 페이지, 공지 상세, 문의·로그아웃 완료, 탈퇴 팝업을 연결.
- 이전 시설 서비스의 검색·필터·지도 마커·상세·이용 현황·주차·주변 행사·안내 및 빈 결과·정보 미제공 상태를 구현. `GET /facilities` 갱신 어댑터 제공.

## 5단계 — 백엔드·실측 데이터 연결 / 다음 협업 단계

1. `API_CONTRACT.md`의 초안과 실제 백엔드 URL/응답/인증 정책을 합의한다.
2. 실제 수집 데이터의 장소 ID, 요금 null, 시간대, 좌표, 원문·신청 링크, 출처 차이 정보를 맞춘다.
3. n8n/수집 작업이 DB 배치 갱신 후 revision/updatedAt을 변경하도록 연결한다. FE는 재조회로 반영한다.
4. AI 조건 해석과 코스 생성/재계산의 실제 응답을 검증한다. 프로그램 시각·운영시간·이동 제약을 확인한다.
5. 계정별 클라우드 코스 보관, 짧은 서버 공유 링크, 푸시 구독·발송을 연결한다.
6. 지도 제공사·키·트래픽 계획과 실제 모바일 기기에서 위치/길찾기를 검증한다.

## 검증

`npm run check`, `npm run build`, `npm test`. Playwright는 모바일 사용자 흐름과 API 대체 응답을 사용한 갱신/실패/재시도를 확인한다. 실제 백엔드·n8n·AI를 실행한 통합 테스트는 아니다. 320px/390px/1280px에서 가로 넘침과 깨진 이미지를 확인한다.
