# 백엔드 없이 확인하는 전체 서비스 흐름

`VITE_API_BASE_URL`을 비우고 `npm run dev`를 실행하면 시연 데이터로 아래 여정을 완주할 수 있다. 백엔드는 별도 담당자가 개발하며, 실제 API가 준비되면 서비스 어댑터를 맞춘다. 백엔드 구현이나 병합을 이 작업의 전제로 두지 않는다.

| 단계    | 사용자 행동                                    | 이어지는 상태                                   |
| ------- | ---------------------------------------------- | ----------------------------------------------- |
| 진입    | `#/onboarding` → 시작하기 → 게스트로 입장      | 로그인 없이 홈 진입                             |
| S1 검색 | ‘이번 주말 기흥구 아이와 야외’ 입력 → 검색     | 조건을 해석한 뒤 행사 목록으로 바로 이동        |
| S2 탐색 | 결과에서 조건 수정 → 목록/지도 전환            | 같은 필터의 행사 결과와 마커                    |
| S3 상세 | 마커 미리보기 → 행사 선택                      | 선택 행사·프로그램·요금·출처·신청 안내          |
| S4 설정 | 이 행사로 하루 짜기 → 아이 나이·출발지 등 입력 | 검색의 날짜·동행·무료 조건 이어받기             |
| S5 일정 | 일정 만들기                                    | 행사·프로그램·식사·근처 행사·귀가 5칸           |
| 편집    | 장소 교체·직접 입력·추가·삭제·순서 변경        | 시간표와 지도 방문 순서 재계산                  |
| 동선    | 지도에서 동선 확인 → 장소/마커 선택            | 주소·운영·요금·갱신 출처 카드                   |
| 보관    | 뒤로 → 저장·공유 → 내 코스에 저장              | 편집한 상태로 브라우저에 보관                   |
| 공유    | 공유 링크 생성 → 다른 브라우저에서 열기        | 출발지·현재 좌표·아이 나이를 제외한 일정 스냅샷 |
| 재방문  | 내 코스 → 코스 열기 → 조건 바꾸기              | 편집/재생성으로 다시 연결                       |

위의 주말 입력은 접속한 날짜 기준으로 해석한다. Figma 예제 행사는 2026-11-14~15로 고정되어 있으므로 다른 주에 확인할 때는 칩에서 그 날짜를 고르거나 행사명으로 검색한다. 자동 테스트는 2026-11-12 서울 시간에 고정한다.

후보 없음·무료 조건 불일치·위치 권한 거부·지도 배경 실패·저장 공간 부족·공유 링크 오류도 각각 다음 행동을 안내한다. 좌표가 없는 장소와 확인되지 않은 가격은 실제값을 지어내서 채우지 않는다.

홈에는 조건 칩과 별도 조건 검색 단계를 두지 않는다. 행사명과 문장을 같은 검색창에서 처리하며, 새 검색·빈 검색·행사 전체 보기는 이전 검색 조건을 초기화한다. 검색 API 실패 시 입력을 유지하고 재시도할 수 있고, 다른 화면으로 이동하면 진행 중 검색 요청을 중단한다.

## 추가 화면과 상태 연결

- `#/conditions`에서 검색 조건을 수정하고 목록으로 돌아간다. 코스 설정의 출발지 링크는 `#/origin/:eventId`이며 입력 후 설정으로 돌아간다.
- 코스 생성은 `#/generating/:eventId`의 대기 → 성공 일정으로 연결된다. 오류는 재시도, 취소는 설정으로 연결되고 요청을 중단한다.
- 일정에서 `#/replace/:courseId?stop=:stopId` 또는 `#/manual/:courseId?stop=:stopId`로 이동하여 선택한 칸에 반영한다. `#/share/:courseId`에서 저장·링크 공유, `#/delete-course/:courseId`에서 삭제를 확인한다.
- `#/saved`의 주간 달력과 `#/calendar`의 월간 달력에서 날짜별 코스·행사를 열 수 있다. 저장 목록은 `#/saved-courses`다.
- 시연 계정 → 계정 정보 → 설정 → 로그아웃 확인·취소·완료가 연결된다. 문의 → 시연 완료에는 실제 전송되지 않았음을 표시한다. 서버 모드는 실제 응답 후 완료로 이동한다.

## 이전 시설 서비스

`#/facilities` → 마커 선택 → 시설 카드 → 상세 → 이용 현황·주차·주변 행사 → 행사 상세로 이동한다. 검색 → 검색어 결과 → 필터의 지역·분류·유형 선택 → 결과 → 상세로도 연결된다. 전체 시설·정보 미제공 시설·빈 검색 결과·필터 초기화·이용 안내도 제공한다. 뒤로 이동 시 검색어와 필터를 유지한다.

이용 인원·정원·주차 면수와 관측 시각을 함께 표시한다. 미제공 값은 0으로 바꾸지 않는다. 가상 배치도와 시연 수치는 명시적으로 표시하며 실제 API 연결 시 좌표 지도로 전환한다. 공식 URL이 없는 시연 버튼은 연결되지 않았다는 안내를 표시한다.

## 전수 비교와 검증

`#/design-review`에서 50개 원본 프레임을 각각 열 수 있다. 화면 비교 모드의 저장·삭제·계정 변경은 일반 localStorage에 반영하지 않는다. 생성 중 상태는 비교 중 자동 전환하지 않는다. 실제 사용 흐름은 일반 경로에서 검증한다.

`tests/journey.spec.ts`는 주 여정을 실제 클릭으로 한 번에 검증한다. `tests/service.spec.ts`는 예외·저장·공유·반응형 동작, `tests/frames.spec.ts`는 전체 프레임과 달력·계정·문의·시설 여정, `tests/remote.spec.ts`와 `tests/states.remote.spec.ts`는 대체 API 응답으로 갱신·실패·복구·생성 취소를 검증한다. 실제 계정 인증·문의 접수·AI 호출·데이터 수집 작업은 서버 연결 이후 확인한다.

## 카카오 키와 배포

배포 주소: https://yongin-festival-guide-2026.brian180099.chatgpt.site

카카오 앱: 용인 나들이 (ID 1650321). 카카오디벨로퍼스의 **앱 → 플랫폼 키**에서 REST API 키와 JavaScript 키를 확인한다. **제품 설정 → 카카오맵**은 활성 상태다.

프론트의 `.env.local`에 `VITE_KAKAO_JAVASCRIPT_KEY`를 설정하고 빌드하면 행사 지도·코스 동선에 카카오 지도 SDK를 사용한다. 키가 없으면 개발용 OpenStreetMap 지도를 사용한다. JavaScript SDK 도메인은 배포 origin과 `http://localhost:5173`, `http://127.0.0.1:5173`을 등록했다.

REST API 키는 Sites의 `KAKAO_REST_API_KEY` 비밀설정에 저장한다. 운영 빌드는 Worker의 `GET /api/places`를 통해 카카오 키워드 검색을 호출하며 홈·검색 목록·지도에 실제 장소를 표시한다. 키는 서버 헤더에서만 사용하며 프론트 환경변수·응답·번들에 포함하지 않는다. 자세한 동작과 검증은 [실제 장소 검색](REAL_PLACE_SEARCH.md)을 참고한다. 실제 행사 일정 수집·계정·코스 생성의 운영 백엔드는 별도다.

자동 테스트에서는 외부 SDK와 실제 키에 의존하지 않도록 지도 키를 비워 기존 지도 여정을 검증한다. 실제 카카오 SDK는 등록된 도메인의 브라우저에서 마커 선택과 장소 카드 연결을 별도로 확인한다.
