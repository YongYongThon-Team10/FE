# 실제 장소 검색

배포 주소: https://yongin-festival-guide-2026.brian180099.chatgpt.site

## 사용자 흐름

운영 빌드는 `.env.production`의 `VITE_PLACES_API_BASE=/api`로 실제 검색을 사용한다. 홈의 장소 검색·가볼 만한 곳·결과 목록·지도는 카카오 REST API에서 받은 장소다. 시연 행사 카드로 대체하지 않는다. 장소 카드에는 카카오가 제공한 장소명·분류·도로명/지번 주소·전화번호와 카카오맵 상세 링크를 표시한다. 운영 시간·요금·행사 일정은 응답에 없으므로 임의로 표시하지 않는다.

검색어·페이지·목록/지도 상태는 `#/places?q=...&page=...&view=map`에 있어 새로고침과 뒤로 가기를 지원한다. 페이지당 15개, 최대 45페이지는 카카오 API 한도이며 마지막 페이지에서는 다음 버튼을 비활성화한다. 용인시 범위 안의 검색을 제공한다. 문장형 추천 AI가 아니라 장소명·업종 키워드 검색이다. 예: 용인중앙시장, 기흥역, 공원, 카페.

빈 결과는 빈 결과 안내, 외부 API 실패·키 미설정·시간 초과는 오류와 재시도 버튼을 표시한다. 취소되거나 오래된 검색 응답은 현재 결과를 덮어쓰지 않는다. 홈에서도 실제 API를 조회하며 실패할 때 가상 추천을 보여주지 않는다.

## 서버와 키

`server/places.mjs`는 같은 출처의 `GET /api/places?q=검색어&page=1` 요청을 처리한다. 서버의 `KAKAO_REST_API_KEY`를 Authorization 헤더로만 카카오에 전달한다. 요청 URL·응답·브라우저 번들에 REST 키를 넣지 않는다. 호출 대상은 카카오 키워드 검색 API로 고정하며 사용자 입력으로 외부 호스트를 선택할 수 없다. 용인 지역 검색어·좌표 범위와 결과 주소를 함께 확인한다.

입력 길이/페이지/메서드 검증, 8초 제한, 인스턴스별 요청 급증 제한을 적용한다. 성공 응답만 60초 캐시할 수 있고 오류는 캐시하지 않는다. 외부 오류 본문이나 키는 사용자에게 전달하지 않는다.

카카오 문서: https://developers.kakao.com/docs/ko/local/dev-guide#search-by-keyword

## 빌드와 배포

`npm run build`는 React/Vite 정적 빌드다. `npm run build:site`는 이어서 `scripts/build-worker.mjs`로 프론트 에셋을 포함한 단일 Worker를 `dist/server/index.js`에 만든다. 별도 정적 에셋 바인딩 없이 기존 앱을 제공하기 위한 방식이다. `.openai/hosting.json`에는 기존 project_id만 유지하고 static 선언을 제거했다. 기존 공개 범위와 배포 주소는 유지한다.

키 값은 Sites 비밀설정에 둔다. JavaScript 키는 로컬 `.env.local`의 `VITE_KAKAO_JAVASCRIPT_KEY`를 빌드에 적용하며 등록된 도메인에서만 지도를 표시한다. REST 키는 VITE_ 변수로 만들지 않는다.

`npm run test:server`는 입력 검증·실제 필드 매핑·키 전달 위치·오류·빈 결과·잘못된 응답을 확인한다. Playwright 실제 검색 모드는 모의 카카오 결과로 목록/지도/상세 링크/페이지/새로고침/재검색 취소를 검증한다. 배포 후 실제 카카오 검색도 별도로 확인한다.

기존 Figma 비교 화면·시연 코스 생성·보관·계정 화면은 유지한다. 카카오 Local은 장소 데이터이며 실제 행사 일정 수집이나 코스 최적화 API가 아니다. 해당 기능의 운영 백엔드 연결은 별도다.
